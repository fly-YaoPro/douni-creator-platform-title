# 平台标题写法

## 抖音

抖音发布标题要补足视频前三秒，而不是逐字复述开头。默认同时满足“可搜索”和“有点击理由”。优先顺序：

1. 明确核心搜索锚点：具体任务、产品、Skill、产物或人群。
2. 从脚本中选择一个真实钩子：冲突、反差、意外用途、结果悬念、数字或迫切痛点。仅罗列结果和功能不算钩子。
3. 用达人自己的教程、经验、观点或展示口吻把两者连成一句话。
4. 若产品/Skill 是内容核心或专项必带，必须保留；不能只留下泛化场景。

写法：

- 通常 14–32 个汉字；信息密度优先，不把长度当硬门槛。
- 教程型可用“任务 + 方法/结果”，例如“把错题自动整理成复习系统”。
- 观点型要保留达人判断，不强行改成教程句。
- 展示型要点出场景与动作，如地点、对象或视觉结果。
- 标题中至少出现一个可检索名词和一个具体点击理由。二者可以共用同一短语，不为满足格式硬拆两截。
- 搜索锚点应使用用户真的会输入的说法，不堆同义词；“豆包Agent”优于“这个AI工具”，“复盘PPT”优于“办公成果”。
- 钩子应落在可验证的信息落差上；“临时要汇报，我把杂乱数据扔给豆包Agent”“不写代码，也做出了3D简历网站”比“3个Skill完成PPT”更有点击理由。
- 推荐标题避免纯功能说明句，例如“豆包Agent用3个Skill完成PPT”“选题、脚本、成片一套完成”。这类信息可以成为搜索候选，但缺少噱头时不能排第一。
- 允许使用第一人称、动作性动词和轻度情绪，但必须与达人脚本口吻一致；“我把……扔给……”“还在……”“没带电脑……”都需要原稿证据。
- 话题标签另列；标题正文不堆 `#`。
- emoji 可不用；使用时最多 1 个且必须帮助语义。

## 小红书

小红书发布标题同时承担搜索和点击入口。优先把用户会搜索的对象放在前半句：

- 对象：错题本、求职、晶胞模型、竞品调研
- 场景：研究生、应届生、老师、打工人
- 结果：拿到 offer、做出互动游戏、完成调研

写法：

- 通常 12–22 个汉字；专有名词较长时可超出，不机械截断。
- 推荐“搜索对象 + 具体收益/经验”，避免只有情绪没有主题。
- 保留真实个人经验口吻；没有亲身证据时不用“我靠这个……”
- emoji 0–1 个可选，不作为必填。
- 不用“合集、教程、经验分享”占满标题但不交代具体内容。

## 封面标题

只有用户明确要封面时才生成。可借用以下三行结构，但不能拿封面文案替代发布标题：

- 对象/场景 → 冲突或结果 → 方法/行动
- 身份点名 → 痛点 → 明确收益
- 新发现 → 关键细节 → 结果

封面可比发布标题更短、更分行；发布标题仍需完整可搜索。

## 机制路由

| 脚本最强证据 | 首选机制 | 避免 |
|---|---|---|
| 清晰教程和产物 | 搜索问题/方法 | 空泛“保姆级教程” |
| 已验证结果 | 明确收益 | 擅自扩大数字 |
| 强身份场景 | 身份点名 | 把所有人都写成目标人群 |
| 新奇工具用法 | 新发现 | “居然还能这样”但不说是什么 |
| 前后变化明显 | 反差 | 制造脚本不存在的冲突 |
| 具体数字可信 | 数字锚点 | 无来源数字 |
| 达人判断鲜明 | 观点 | 改成通用教程腔 |
| 内容依赖热点 | 热点 | 蹭无关热点 |

## 抖音内部候选评分

推荐标题从内部候选中按以下顺序取舍，不向用户展示分数：

1. 脚本可兑现、没有跑题。
2. 有信息落差，能让用户产生一个视频会回答的问题。
3. 核心搜索词清楚且自然。
4. 符合达人口吻，不像品牌广告。
5. 没有机械复述视频前三秒。

搜索很准但没有信息落差的标题不能直接成为推荐；钩子很强但删掉核心主题的标题同样不能成为推荐。推荐标题不能因为安全而自动选择三档里最平的一档。
